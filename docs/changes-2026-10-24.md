# 角色切换、聊天强调与加载检查

## 已完成

- F1：角色、聊天文件名、元数据和正文先在局部变量中准备，读取成功后一起切换。读取失败或聊天响应不是数组时，保留旧会话和输入草稿；下一次保存仍指向原角色。偏好保存失败时，已加载的会话也保持身份与正文一致。
- Markdown：现有 Showdown 已支持 `**加粗**`、`*斜体*`、列表、引用、代码等。页面原有 `font-synthesis:none` 加上仅声明常规字重的本地字体，可能抑制实际强调效果；现在正文允许字重和斜体合成，并明确 strong/b 为 700 字重。原始消息内容不变，代码块内的星号仍按代码展示。
- 打开角色：角色资料和聊天列表改为并行请求。等待由两者耗时之和变为两者中较慢的一项（不含后续聊天读取和宿主资源争用）。
- 保存角色入口：lastCharacter 与 lastChats 合并为一次设置事务；两者均未变化时跳过设置写入。原先首次切换到未记录聊天可能执行两次 saveOwn，现在只需一次；每次 saveOwn 涉及最新设置读取、写入和核验读取。

## 角色加载后续优化方向

| 路径 | 当前成本 | 下一步建议 |
|---|---|---|
| 首次打开角色库 | `/api/characters/all` 对所有 PNG 执行 processCharacter，前端等完整列表；之后已有会话内缓存和每页 60 张分页 | 在宿主副本测量 PNG 解析、响应体大小、卡数；视结果增加按文件修改时间失效的轻量角色索引与分页接口 |
| 打开某角色的聊天 | 宿主 `/api/characters/chats` 为全部聊天获取详情，页面仅用文件名和时间选择目标 | 增加只返回文件名与 mtime 的接口，必须明确“最新”按文件修改时间还是消息时间；不能直接切换 simple 模式，因为该模式没有排序时间 |
| 封面图片 | 角色库和首页使用原图，已有 lazy loading 与 async decoding | 本次保留清晰度；如网络测量显示图片是瓶颈，再考虑可选缩略图/渐进加载及版本缓存 |

以上是源码定位结果，未在真实角色库、手机或网络上测量，因此不承诺提速百分比。未修改宿主服务器或用户数据。
