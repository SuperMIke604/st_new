# 加载、缓存与性能约束

核对日期：2026-10-26。加载链路、缓存键/失效、计时语义或测量基线改变时更新；源码参数是精确依据。以下源码相对 `public/app/`。

## 已实现链路

- `index.html → theme-init.js` 在 CSS 前恢复主题，再加载本地 Markdown 依赖和 `main.js` 模块。
- `start` 先连后端取得 CSRF，再并行读取最近角色与连接文件，同时完成设置和预设初始化；等待各阶段结束后收起启动状态。连接初始化失败可保留资料查看，生成前仍阻止发送。
- `bootstrapSettings` 优先自有插件接口，404 回退原生设置；`RecentCharacters` 同样优先轻量 recent。插件 bootstrap 仍读取全部 OpenAI 预设正文，不是只读取选中的一份。
- 完整角色库按需加载；`openCharacter` 并行读取单卡和聊天列表，随后读取聊天，成功后一起提交会话。
- 角色卡正则和脚本管理优先复用已加载目录（允许超出普通目录 30 秒缓存期限，角色增删仍使缓存失效）；无完整目录时使用当前/最近角色和显式目标，只读取选中单卡。“全部角色”或“刷新角色列表”才请求完整目录。服务端插件未启用或轻量接口缺失时，此显式操作仍可能回退到较大的原生全部角色响应。
- 角色库优先使用自有插件轻量目录，只传名称、头像标识和日期；PNG 仅读元数据，单卡正文按需走原生 get。世界书列表优先使用插件文件投影缓存，按文件状态重读变化项，四路并发代替逐本串行读取；两个目录接口仅 404 回退原生，500/认证/网络错误保留失败。插件缺失时仍有原生大响应开销，升级插件并重启后生效。后端缓存边界见集成契约。
- `loadPanelContent` 先让加载指示绘制，再准备内容；revision/token 拒绝旧结果。预设计数有 `_dispose` 取消与 `_onReady` 后台任务约定。
- 生成及保存链路见 [生成流程](../generation-flow.md)；必要的保存、精确计数与动态宏不能因优化被省略。

## 缓存与失效索引

| 所有者 | 缓存内容和边界 | 修改时关注 |
|---|---|---|
| `TavernAPI.readCache` | allowlist 读取，世界书约 60 秒、其他约 5 秒；无 signal 才缓存，复用进行中请求并克隆返回 | 非缓存请求除 tokenizer/generate 外通常清空缓存；外部客户端修改未必即时可见 |
| `RecentCharacters` | 最近入口约 30 秒，合并请求 | `rememberChat` 等主动失效；不等于完整角色目录 |
| `CharacterCatalog` | 非空角色目录约 30 秒、revision、防异常空列表重试 | 变更角色后失效；signal 绕过通用短缓存 |
| `GenerationPreload` | 两份资料库文本/宏；依据 header、seed、配置和消息来源 | 保存聊天清空；原地修改对象可能影响引用比较，须检查实际失效 |
| `HistoryRegexCache` | 纯提示词正则结果，分区缓存与分片预热，完整文本条数按实际保留结果增长（512–4096），总字符不超过 800 万；过滤为空的正文使用消息弱引用标记 | 含动态宏规则实时执行；不能缓存变量展开结果 |
| `PresetTokenPreview` | 有界精确计数，默认最多 2 个并发 | 切面板/关闭/重排取消；数据库和世界书按需共用 |
| `main.js tokenCounts` | 正式请求精确计数，有界内存缓存 | 按模型和完整消息区分；预览结果不能取代正式预算 |
| `VirtualChat` | 可视＋缓冲最多 40 个消息节点，高度记录 | 保留节点不要重新挂载 iframe；完整聊天仍在内存 |

角色聊天成功加载并保存聊天位置、解除 loading 后，以及回复保存和自动填表结束后，约 150ms 延迟预加载，读取世界书、准备普通/重生成资料，并分片预热纯正则；进入角色、切换历史聊天和新建聊天均覆盖，内部聊天加载只由外层角色入口调度一次。切换开始时取消旧预热，读取失败不调度，直接发送仍取消未完成预热并按正常流程补齐计算；不预调用模型、不预抽取激活概率、不替代发送时的动态上下文。

## 如何测量

`load-timings.js` 保存最近 200 条标签页记录，刷新后保留；请求计时到响应头，页面计时含解析与渲染。仅记录无查询参数的接口路径及受限详情，不记录正文或密钥。兼容回退、取消、刷新中断不等于请求失败。

生成诊断随同一份 JSON 导出：助手初始化、四个生成事件（包含快照准备与事件等待）、角色变量准备/更新、资料库文本准备、世界书激活、历史消息正则与宏展开、请求组装、发送前列表刷新及各次聊天保存分别计时。构建子阶段嵌套在构建总计内，不应相加；精确计数继续查看 tokenizer 请求。模型另记请求至响应头、首段非空文本（包含思考）、回复接收完成；三项均从请求前起算，彼此重叠，非流式首段文本只在完整 JSON 解析后可见。未收到文本便取消/失败时对应记录标记取消/失败，不冒充首字成功。后台正则预热单独记录，累计实际计算与分片等待；同一聊天资料的重复触发合并，替换任务等待旧任务退出，发送/失效会取消旧任务。只添加固定阶段名，不记录脚本正文、变量值、聊天内容或连接地址。

性能任务先固定部署版本、宿主/插件、浏览器/设备、网络、数据规模与冷热缓存状态，分开记录：

1. 首屏可用、管理页可用、角色/聊天切换。
2. 点击发送到模型请求发出、请求到首字、流结束到保存和解除 busy。
3. 构建、tokenizer 次数与耗时、保存体积、长任务、iframe 重建次数。

不在日志中带入私有正文。多次样本才讨论分布和 P50/P95；单次结果只报告单次观察。

[预设专项](../preset-loading-performance.md) 和生成文档中的旧对照是当时环境的历史证据，不是当前设备或全部流程的性能承诺。

## 潜在开销与验收底线

聊天保存分别记录快照复制、等待保存队列、JSON 序列化、压缩准备及原生 HTTP 请求时间。传输详情只记录原始/上传字节数和 gzip/回退标记，不记录正文。大请求可使用原生 gzip 解压能力压缩上传，具体兼容边界见集成契约；这只减少传输和重复序列化，不减少后端整文件校验、落盘和备份，也不省略助手事件前后必要的保存。HTTP 请求耗时仍同时包含上传、服务端处理和返回，不能仅据此归因为磁盘慢。

历史处理详情记录当次缓存命中、未命中、动态规则跳过、无适用规则、超限未缓存、淘汰及配置失效数量，并累计正则处理和宏展开耗时；只记录数值，不导出正文或规则内容。后台预热记录完成或提前取消及本任务处理数量，分片之间其他任务的缓存访问不计入本任务。日志使用独立窗口，刷新列表、导出、清空不进入聊天/编辑面板生命周期，也不操作生成控制器；清空保留正在计时的记录。移动端日志窗口覆盖整个可视区域，记录逐条排列并直接显示详情；桌面保持表格布局。

完整历史复制/序列化、资料快照、全部预设/角色读取、同步正则和流式 Markdown/HTML 处理有规模相关成本；未测量时只列候选，不称已确认瓶颈。

优化后应比较请求消息与预算、未知字段、保存回读、候选分支和变量、旧数据兼容、切换取消及失败重试。不能把保存移到后台后忽略失败，也不能用粗略估算替换正式精确计数。测试入口包括 `startup-loading`、`panel-loading`、`chat-session`、`virtual-chat`、`generation-loading`、`generation-preload`、`history-regex-cache`、`preset-tokens`、`load-timings`；按影响选取，不固定测试总数。

同一预热键包含聊天身份、消息正文/可见性、正则配置和资料库配置；成功任务复用直到键变化或失效，失败/提前退出允许重试。完整文本缓存按当次可缓存且非空的处理结果数预留两倍条数与少量余量，最多 4096 项，总字符上限不变；只有完整扫描成功后才按有效结果数缩小容量，取消任务不据部分历史缩容。命中项进入受保护区（最多占条数和字符上限的 80%），顺序扫描优先淘汰冷项。日志分开记录条数/字符上限引发的淘汰、正则实际执行时间与缓存容量，避免把调度等待误算为计算。

纯正则处理结果严格为空字符串时，按消息对象弱引用保存原始正文引用和适用规则组标记（每个消息最多四组），不另拼接完整正文作为缓存键，也不占完整文本缓存条数。正文改变、深度变化使适用规则组变化或正则配置变化时重新计算；动态正则仍实时处理，不走空标记。未被隐藏的历史仍按原序检查并处理，不依据固定楼层数直接跳过，也不提前跳过动态宏副作用、附件校验或名字前缀。后台预热不处理已隐藏消息；正式构建仍保留原深度语义。日志增加正则过滤为空数、空标记命中/新建数和宏/名字处理后的非空历史数，二者在名字前缀模式下可能不同。弱引用标记的对象元数据不计入完整文本字符容量；聊天本身仍保留原文。

导出 schema 3 包含构建摘要、生成关联 ID、导出时生成/取消状态、预热调度累计数和缓存容量；记录页面隐藏/离开/恢复，主动停止与网络/离开原因可区分。记录存储合并到约 100ms 一批，页面离开时强制写入；内存快照即时可见。生成中导出只在日志窗口保留只读快照，可立即复制；生成结束后手动下载同一快照，期间不会发起下载或导航。空闲下载使用新上下文目标，避免替换主页面。旧文件只描述导出之前的状态，不能据此认定导出后是否断流。

管理页加载诊断以页面总记录 ID 为 parentId，跨并行/过期页面显式传递作用域，不使用全局当前页面标记。总耗时包含加载指示绘制等待、初始化等待（如有）、内容准备、DOM 挂载和下一帧等待；其中内容准备再细分数据读取/整理及列表构建，嵌套阶段不可相加。世界书记录全局选择器、条目数据与列表；角色卡记录目录内存缓存/共享读取、分类整理、筛选排序和可见卡片构建；正则与脚本记录分类来源、规则/脚本数据和列表。分类编号 1–5 依次对应全局正则、预设正则、角色正则、全局脚本、角色脚本。接口级记录响应头、响应体接收、JSON 解析、结果复制和读取缓存复用，缓存复用标记开始时是否等待共享请求。日志只保留接口路径、数量和数字标记，不能带资源名称或内容。页面总记录补充 DOM 节点/图片/未完成图片数量；下一帧等待不是全部图片解码完成或精确 GPU 绘制测量。

世界书列表保留全部条目摘要、启停、激活方式、顺序和位置控件，完整编辑表单仅在首次展开时创建，收起再展开复用同一表单；草稿始终包含全部原始字段，导出和保存不依赖哪些条目已展开。屏幕外条目通过 content-visibility 降低绘制成本，不支持的浏览器正常显示完整列表。重建列表、切换世界书和关闭面板会清理计数定时器并使旧回调失效；未展开条目不发起 token 计数。
