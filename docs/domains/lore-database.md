# 剧情资料库：模型、归属与兼容

核对日期：2026-10-27，依据当前工作区；数据模型、快照生命周期或适配改变时更新。默认开发范围是提取结果的接收、解析、保存、更新和展示；未经明确要求不优化提示词或重设提取流程。

## 源码与模型

源码均位于 `public/app/`：`database.js` 管契约和配置适配，`database-reference.js` 管参考解析/操作/旧消息抽取，`database-defaults.js` 保存参考默认配置，`database-ui.js` 管管理界面，`database-preview.js` 管卡片、差异、分页与单元格编辑，`database-overview.js` 管当前聊天历史汇总、概览及删除回退。实际请求和持久化由 `main.js` 的 `currentDatabase/databasePanel/updateDatabase/autoUpdateDatabase` 协调。

资料库是当前聊天上的 `chatSheets` 表格快照，不是固定人物/事件实体服务。`defaultDatabase()` 的回退表为当前状态、人物、事件；不代表真实聊天类型或模板固定。

| 结构 | 契约 |
|---|---|
| `mate.type` | `chatSheets`；验证器可补缺省 mate，拒绝不兼容类型 |
| `sheet_*` | 表键；`sheets()` 用正则筛选，表含 `name/content`，保留其他元数据 |
| `content[0]` | 表头；首列为占位结构，有效字段从第二列开始 |
| 后续行 | 同表头长度，单元格允许 null、文字、数字、布尔值 |
| 行与列 | 操作的行号从数据行 0 开始、列号从有效列 0 开始，不能与二维数组物理索引混用 |
| 数据关系 | 当前主要由单元格表达；没有稳定实体 ID、外键或跨表关系约束 |

`validateDatabase` 克隆并校验，不主动删除未知字段。不要从旧 README 推导存在统一的 3MB/100表/5000行/64列强制限制；当前验证器未实施该整套限制。

## 快照生命周期

| 数据 | 位置 |
|---|---|
| AI 回复快照 | `message.TavernDB_ACU_Data` |
| 来源和更新时间 | `message.extra.independentDatabase`，含 `sourceHash/updatedAt` 及调用方元数据 |
| 无消息快照时的种子 | `header.chat_metadata.independentDatabase.seed` |
| 覆盖前历史 | `header.chat_metadata.independentDatabase.history` |

`databaseForChat` 从后向前查非用户消息，优先结构化数据，再用参考函数抽取旧标签/围栏等显式载体；没有时取 seed，再取模板。旧快照无前端元信息时标为 legacy，不自动批量迁移。

`storeDatabase` 校验后附着到指定 AI 回复，或在 index=-1 时写 seed；覆盖不同旧值时存历史，并标记后续快照 stale。历史最多 8 项，且按 `JSON.stringify(history).length` 约 200 万字符收缩，不是字节精确的备份配额。

`invalidateDatabases` 标记来源变化；**读取当前仍可能选中 stale 快照**，不能擅自改成过滤规则。已有测试明确覆盖该行为。`sourceHash` 主要覆盖消息角色、名称、正文与位置，不是整个会话的并发版本或安全哈希。

会话用头像文件名和聊天文件名定位。消息编辑、删除、重新生成、候选切换还会涉及分支、变量和快照联动，须同时查 `main.js` 的消息操作，不只改数据库模块。

## 配置、更新和展示

- 配置属于前端 own 设置中的 `database`；`databaseSettings/migrateLegacySettings` 适配 `charCardPrompts`、`overviewTemplate`、API 和预设字段。保留未知字段并维护原字段导出映射，不按命名猜测两个设置必然同义。
- 每份填表预设有自己的模板；切换或编辑模板不应直接覆盖已有聊天快照。应用到当前聊天是独立动作。
- 模板页先选择所属 AI 指令预设，再通过表格导航编辑表名及字段；支持增删表、增删字段与撤销，每张表至少保留一个有效字段。字段增删同步调整已有模板数据行；删除表或字段会确认，保存前仍为草稿。切换所属预设保留上一预设的模板草稿并清空当前撤销栈，不改变两类总结的执行预设绑定。
- 状态与操作分为数据库状态、消息总结、数据库总结。`activePreset` 仅表示正在编辑的预设；`messageSummaryPreset/databaseSummaryPreset` 独立绑定执行预设，编辑器切换不会改变绑定。旧配置保留原消息总结预设，首次适配新增数据库总结预设；删除绑定预设时回退到保留的预设。其余未知配置继续保留，废弃的 `autoHideMessages` 字段在适配时移除。
- 状态与操作中的配置仅在点击该页“保存配置”后持久化；其他标签页的自动或手动保存不夹带该页草稿。存在未保存配置时执行总结须先保存，执行按钮不会隐式保存；保存失败保留草稿和未保存状态。保存队列执行时合入最新已保存状态，避免排队的其他标签页保存覆盖刚提交的状态配置。
- 消息总结沿用保留最新 N 层、每批楼层数和标签处理配置。数据库总结仅处理最新快照的完整表格，不发送楼层对话；默认预设合并冗余记录，以原表键和表头返回更新。总 Token 按总结连接模型调用后端 tokenizer 统计完整表格文本（含消息封装），指定表条数不含表头。两阈值为“或”，0 禁用对应条件，缺失的表不会触发条数条件；已达条数阈值不依赖 tokenizer 可用性。
- 自动任务在回复保存后检查，先消息总结再数据库总结；任一任务停止或失败则终止本轮后续操作。数据库总结写回最新快照楼层，保留覆盖前历史和消息总结进度；同一总结快照不会再次自动总结，后续消息或人工保存产生新快照后可重新检查。提交前另行校验最新快照未被其他操作替换。
- 更新范围选取后复制聊天和当前数据，读取参考资料，经原生生成接口得到结果，调用 `parseUpdate → referenceUpdate`。不要误用同文件另一个 `applyOperations` 替换参考容错路径。
- AI 更新响应兼容仅含 `operations` 数组的完整 JSON 对象，可省略 `<dataUpdate>` 标签。兼容分支沿用同一操作解析、计数和保存校验。整表替换及夹杂说明文字的响应仍需要显式 `<dataUpdate>` 块。带标签的增量操作可兜底转义独占一行、边界明确的数字列单元格正文中的双引号，修复成功会在更新日志中标记。
- `<dataUpdate>` 内的 JSON 纠错保留字符串正文，允许组合修复结构分隔符和单处 `operations[i].data` 结束括号错配。每条完整操作与下一条操作或数组结尾之间允许删除一个多余的右花括号。若 `insert` 的 `data` 已完整闭合，且字段为数字列索引和有效单元格值，可在同样的边界补齐该操作缺失的右花括号。修正后的完整 JSON 须通过解析。括号缺失或多余且无法确定修法时，记录解析失败并保留原响应。
- 更新成功提示在保存完成后显示，汇总各批次参考解析器实际成功应用的增删改操作数，例如“数据更新成功，共应用 12 条更新”；按操作数计数，不按净增行数或唯一行数计数，跳过的无效操作不计入。整表替换按参考插件口径单独显示更新表格数，不虚构更新条数。
- 数据管理的“更新日志”保留当前页面最近 50 条手动和自动更新记录，可刷新列表、复制、导出或清空。界面与剪贴板只显示阶段、楼层、耗时、HTTP 状态及解析摘要。JSON 导出附带最近一次格式异常的完整模型回复、HTTP 响应体或无法解析的 SSE 事件数据，原文可能含私密信息。日志及异常原文只保存在内存，刷新浏览器或清空日志时释放。
- 填表使用独立的任务状态和停止控制器，不占用对话生成的忙碌状态、停止按钮或进度提示；管理设置和预览保存可在对话生成期间进行。自动填表仍在回复保存后调度，同一时间只运行一个填表任务。
- 模型更新提交前复核聊天文件标识、截至目标楼层的来源内容与回复分支、数据库快照及其元数据，并检查取消状态。同一聊天重载后这些内容一致时，将结果写入当前聊天对象，保留已保存的变量等其他字段。允许后续新增消息或继续生成，不以其他面板草稿阻止提交。正在保存变量或目标楼层正在生成时阻止写入；来源或数据库冲突时明确拒绝覆盖。预览编辑仍要求当前面板持有原聊天对象。更新结束不重新打开管理页面，也不清除其他页面草稿。
- 解析阶段失败或停止不会提交部分批次。`storeDatabase` 之后落盘失败时内存已经改变，需重试/回读验收，不能笼统声称所有失败都恢复原内存。
- 快照通过完整聊天保存。两类总结均不再自动修改楼层 `is_system`；此前已经隐藏的楼层保留其原状态。
- 数据管理的“数据概览”按版本和表分页展示当前聊天的楼层快照、旧格式总结、聊天种子及现存覆盖前版本。保留 stale 标记，异常快照单独计数。单条或全部删除先标记为待删除，可撤销，点击保存后一次提交。保存前核对打开面板时的聊天及标记时的快照，生成或填表期间禁止提交，保存失败回滚并保留待删除标记。删除只修改数据库字段。
- 新覆盖前版本保留原快照元数据，归档时间单独记录。数据库总结覆盖同层消息总结时，即使表格内容一致也归档被覆盖的消息总结。单独删除数据库总结时优先恢复同层、同源、未标记删除的消息总结，并移除已恢复的归档项。旧归档可用同层覆盖前快照回退，界面只显示可确认的原类型。无可恢复版本时写入 `snapshotDeleted` 标记，避免旧格式正文重新生成已删除的快照。全部删除同时清除归档和种子。历史保留上限不变。
- 预览按表显示、差异筛选、分页和原位编辑；修改先由宿主保存回调持久化，失败恢复预览局部数据。管理历史恢复、撤销不等于磁盘完整备份。
- `generationDatabaseResources` 将表格文本和 `tabledata/sheet_*` 宏临时用于请求，纳入精确预算，不创建虚假聊天楼层。

批准的产品差异与参考提交见 [迁移基准](../../public/app/DATABASE-PARITY.md)。数据库不向世界书同步写入；作为填表参考读取世界书是另一项能力。

## 已知待办与验证

自动总结范围已按本轮重写验证；无变化响应仍保留原解析行为：

- 自动消息范围用 -1 表示尚无进度，包含 0 楼；批次末尾是用户消息时等待下一条可用角色回复，不越过保留的最新楼层。
- `defaultFillPrompt` 允许空 operations，但 `parseUpdate` 对 `changed=false` 抛错；现有测试也断言抛错。修复应先明确成功无变化和进度语义，不擅自修改提示词规避问题。

数据相关改动优先检查 `tests/database.test.mjs`、`database-reference.test.mjs`、`database-concurrency.test.mjs`、`database-overview.test.mjs`、`database-preview.test.mjs`、`generation-preload.test.mjs`；若涉及消息/变量/分支，扩大至相应测试与隔离后端回读。验收应覆盖旧格式、未知字段、模板独立、快照覆盖历史、停止、落盘失败和会话隔离。测试命令见 [开发流程](../development.md)。
