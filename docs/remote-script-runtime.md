# 远程脚本与独立助手宿主

当前接口开放规则：完整助手宿主也装载到普通全局/角色脚本，不要求远程 MVU 身份。所有运行脚本采用同一接口集和操作限制，详见 [原生接口规则](scripts-compatibility.md)。下文的原模块加载及历史验收不代表接口仅供该模块调用；其中“全局脚本不执行”已被统一运行入口取代。

加载兼容补充：同一路径的 MVU `beta` 或 40 位提交 SHA，以及锁定 SHA 的 StageDog `dist/util/mvu_zod.js` 结构注册脚本支持 testingcf / cdn.jsdelivr 两源加载。两源必须指向相同版本；首源成功时不重复运行备用源。公共库加载后，先执行原结构注册脚本，再加载原 MVU 模块并等待异步初始化；结构加载失败会阻止 MVU 就绪，不回退为自制实现。所有普通脚本也可使用 `waitGlobalInitialized`、`errorCatched` 和合并作用域的 `getAllVariables`，仍遵守原有数据边界。原生插件最低版本提示仍保留，助手版本仍如实返回 0.1.0。

文档约定（2026-10-26）：本文对应当时工作区的远程模块实现，写入体系时该实现及本文已有未提交成果；是否提交、推送和部署应实时核对。下文实际验收保留原记录，本次文档整理未重复执行。原模块接入、助手 API、隔离、保存或事件时序改变时更新本文；全局持久化位置和宿主兼容见 [集成契约](sillytavern-integration.md)，其他脚本路径见 [兼容范围](scripts-compatibility.md)。

项目提供酒馆助手所承担的运行环境与接口，让原始脚本负责业务。MVU 的初始化解析、JSONPatch、旧式命令、schema、display_data、delta_data 和设置组件都来自远程原模块，项目不实现另一套 MVU。

## 加载范围与版本

目前仅接入用户明确指定的入口：

```javascript
import 'https://testingcf.jsdelivr.net/gh/MagicalAstrogy/MagVarUpdate@beta/artifact/bundle.js'
```

支持入口前后注释、引号及分号，使用浏览器原生 ES 模块导入；不改写、内嵌或重新打包其业务代码。停用脚本和全局脚本不执行，其他远程入口尚未开放。公共库使用该项目 webpack 声明的真实外部库：Vue 3.5.21、lodash 4.17.21、YAML 2.8.0、Zod 4.1.11。所有库获取成功后才替换对应命名空间。

独立助手 API 当前版本为 **0.1.0**，`getTavernHelperVersion()` 如实返回此值，因此原版 MVU 的最低 3.4.17 检查仍会提示版本不足。这不是本机原生插件版本检测结果，也没有通过伪造版本号掩盖未接入的接口。核心流程已经验证，尚不等于完整酒馆助手兼容。

## 隔离与兼容父容器

外层 iframe 保持不带 `allow-same-origin`，不向脚本传递模型连接、API 密钥或真实应用 DOM。仅允许从指定 CDN 加载模块；任意 fetch、模型端点和媒体网络请求继续受限。

脚本环境内把可替换的 `window.parent` 指向自身兼容文档，提供 `#tavern_helper` 注册容器、`#extensions_settings2` 设置容器、常用原生类样式和 SmartTheme 主题变量。真实应用顶层 `window.top` 仍跨域不可访问。消息桥接在替换前捕获真实父窗口，只接受该窗口的响应；宿主仍核对 iframe 来源、脚本启用状态、脚本身份与聊天身份。浏览器探针已验证可访问兼容父容器且不可访问真实顶层文档。

脚本面板新增“脚本设置”，打开的是原模块挂载的设置组件。没有复制原脚本的设置表单和业务逻辑。

## 已接入的核心接口

- `SillyTavern.saveChat`：按批次保存消息变量、聊天变量及已加载消息的正文修改；不支持通过该接口插入、删除消息或改变回复结构。
- `getVariables`、`replaceVariables`、`updateVariablesWith`、`insertOrAssignVariables`：聊天、消息和全局变量读写；角色变量当前只读。异步更新串行执行，失败后可恢复，避免两个更新覆盖彼此。
- `getChatMessages`：单楼层、负索引、范围、role 过滤，以及有界的完整分支数据。`setChatMessages` 可改已有消息正文和分支变量，保留其他消息、旧回复及未知元数据。
- `getCurrentChatId`、`getCharacterCardFields` 的名称和描述、`getContext`、事件常量与异步事件总线、可停止监听器、once、等待单次事件。
- `saveSettingsDebounced`：保存独立助手的脚本设置命名空间，不复制应用连接配置；快速连续修改保留最终值。脚本按钮查询、追加与替换，按调用脚本身份保存。
- 当前角色及已启用全局世界书的读取，`getCharWorldbookNames`、旧式 lorebook 名称/条目接口、有限宏替换（char/user）。
- `getLorebookSettings`/`setLorebookSettings`：已接入扫描深度、预算、预算上限、递归步数、递归、大小写和全词匹配；其他高级字段目前仅保存在助手配置中，未全部接入提示词引擎。不能据此声称完整世界书设置兼容。
- 原脚本的确认/文本/输入弹窗、通知、设置容器和抽屉交互。工具调用能力明确返回不支持，不用空函数假装成功。

设置保存在 `extension_settings.independentHelper`；全局变量沿用 `extension_settings.variables.global`。每次写入均校验格式、大小、当前聊天、回复分支、消息修订和旧变量值；完整批次验证后才保存，再从后端回读核验。保留生成流程和脚本持有的消息对象身份。失效、停用、未授权或重启后的脚本请求被拒绝。初始化和事件超时停止环境，防止迟到回调继续写入。

新聊天首次落盘也可由助手变量或消息写入触发：仅当当前聊天尚未保存且后端返回空记录时，使用内存中的聊天头和开场消息作为校验基线，保存后回读核验。已保存聊天缺失或后端响应格式异常时仍拒绝写入，不自动重建历史聊天。

## 与生成流程连接

生成前等待原模块的异步 jQuery ready 初始化，发送 `generation_started`；用户消息就绪时发送 `message_sent`。完整模型原文先保存，再交给原模块的 `message_received` 事件处理，完成后才应用显示正则。生成结束发送 `generation_ended`。处理错误保留已收到的回复并显示原因。

重新生成在新分支中处理变量，旧分支文本和变量均保留。关闭或切换聊天会销毁旧环境。仅刷新变量快照不伪造一次新的消息接收事件，避免重复更新。

上下文保留楼层编号，正文与候选分支共享 2MB 字符预算，变量另有 2MB 预算；只提供最近 40 楼的有限正文与有界快照。单楼正文上限 100KB，候选总正文上限 500KB。超出范围的数据明确标记不可用，读取或覆盖时明确报错，不把截断正文当作完整消息写回。修订指纹缓存避免每次刷新重新扫描所有历史正文。

## 实际验收

2026-10-26 先用空白内存环境，再用真实 SillyTavern 后端的独立临时聊天执行用户指定的原始 beta 模块：

1. 原模块自行从测试世界书读取 InitVar，生成初始 `score = 2` 及原生 schema/display_data 等数据并保存。
2. 新回复中的 JSONPatch 由原模块执行，当前值变为 5；真实后端保存并回读核验。
3. 重新生成从前楼基线得到新分支值 9，旧分支值 5 保持不变。
4. 销毁并重启脚本后，回读仍为新分支 9、旧分支 5，没有重复应用补丁。
5. 新回复中的 `_.set('score', 11);` 由原模块解析并保存为 11，重启回读仍为 11；此前旧分支 5 和重新生成分支 9 保留。
6. 原模块设置组件可以打开。浏览器通知勾选测试被自动审批拦截，点击未执行；设置保存、连续修改、命名空间和过期数据校验改用隔离自动化测试验证。

本轮自动测试 224 项：222 通过，2 项因缺少对应后端集成前置条件而跳过。测试没有调用模型，没有修改原聊天。后端验收中世界书和设置使用独立内存副本，只有临时聊天真实持久化；不把设置的内存测试说成真实全局设置写入验收。临时聊天与测试页面在结束后清理。
